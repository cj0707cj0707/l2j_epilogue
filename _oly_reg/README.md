# Удалённая регистрация на олимпиаду: команда `/oly` / `//oly` / `.oly`

> Правка от 14.09.2026. Задача: дать игрокам возможность регистрироваться на **бесклассовые**
> (внеклассовые, class-irrelevant) бои Гранд Олимпиады дистанционно, из любой точки мира,
> без необходимости подходить к Grand Olympiad Manager.
> **Статус: установлен** (патч ядра — в `libs\GameServer.jar` при остановленном GS; скрипты —
> подхватываются при компиляции на старте). В игре не проверялся — проверку выполняет администратор.

## Что получилось (пользовательский опыт)

Любой игрок (ноблес) вводит в чате:

| Ввод | Маршрут | Результат |
|---|---|---|
| `/oly` | Say2 → `ChatGeneral` → алиас «oly» | регистрация на бесклассовый бой |
| `//oly` | клиент шлёт `SendBypassBuildCmd("oly")` → ядро → `admin_oly` | регистрация на бесклассовый бой |
| `.oly` | Say2 → `ChatGeneral` → voiced-хендлер | регистрация на бесклассовый бой |

Сабкоманды (работают с любым из трёх префиксов):

| Команда | Действие |
|---|---|
| `oly` / `oly reg` | регистрация на бесклассовую олимпиаду (`Olympiad.registerNoble(player, false)`) |
| `oly cancel` (`unreg`, `unregister`) | отмена регистрации (`Olympiad.unRegisterNoble(player)`) |
| `oly status` (`stat`) | период олимпиады, очки, победы/поражения, лист ожидания, «в листе ли ты» |
| любой другой текст | подсказка по использованию |

Все проверки и штатные сообщения ядра сохранены: не ноблес, сабкласс, базовый класс, меньше
5 очков, инвентарь > 80%, «уже в списке», «уже выбран в матч», период олимпиады закрыт,
проклятое оружие, участие в ивентах — всё это обрабатывает `Olympiad.registerNoble` /
`unRegisterNoble`, то есть поведение в точности совпадает с кнопками у NPC-менеджера.
Успешная регистрация отправляет системное сообщение ядра + одну строку с числом ожидающих.

## Почему нужен был патч ядра

- `//команда` из чата клиент отправляет пакетом `SendBypassBuildCmd`, ядро вызывает
  `AdminCommandHandler.onCommand(player, "admin_" + текст, true)`. У этого метода жёсткий
  гейт `if (player.isGM())` — обычные игроки туда не попадали вообще.
- Патч (одна строка): гейт заменён на
  `player.isGM() || AdminData.getInstance().hasAccess(command, player.getAccessLevel())`.
  `hasAccess` сравнивает уровень доступа игрока с уровнем команды из `AdminCommands.xml`
  (точно или по цепочке childAccess). Все 469 существующих команд имеют accessLevel 10–100,
  поэтому для них патч — строгий no-op (уровень 0 не проходит). Новая команда `oly` объявлена
  с `accessLevel="0"` — доступна обычным игрокам (уровень 0 = User) и всем ГМ-уровням
  (10→0, 20→10→0, … — все их child-цепочки содержат 0). Забаненные (-1) не проходят.
- `Player.getAccessLevel()` никогда не возвращает null (лениво инициализируется уровнем 0) —
  проверено декомпиляцией.

## Изменённые файлы

| Слой | Файл | Правка |
|---|---|---|
| Скрипты (новый) | `game\data\scripts\handlers\chat\commands\voiced\Oly.java` | voiced-хендлер `.oly` (команда `oly`); статические `register/unRegister/status/dispatch` — общая логика для всех трёх префиксов |
| Скрипты (новый) | `game\data\scripts\handlers\chat\commands\admin\AdminOly.java` | админ-хендлер `admin_oly` (`//oly`), делегирует в `Oly.dispatch` |
| Скрипты | `game\data\scripts\handlers\MasterHandler.java` | импорты + регистрация `AdminOly` (секция admin) и `Oly` (секция voiced) |
| Скрипты | `game\data\scripts\handlers\chat\channels\ChatGeneral.java` | алиас: текст, начинающийся с `/` (или `//`), чей первый токен — `oly`, уходит в voiced-хендлер вместо широковещания; любой другой `/...`-текст broadcastится как раньше |
| Конфиг | `game\config\AdminCommands.xml` | `<admin command="oly" ... accessLevel="0" />` (без префикса `admin_` — как принято в этом файле) |
| Ядро (JAR) | `org\l2jmobius\gameserver\handler\AdminCommandHandler.java` | гейт `isGM()` → `isGM() || hasAccess(...)` в `onCommand` |

## Механика загрузки (почему именно так)

- Скрипты `handlers\*` исключены в `Scripts.xml`, но `GameServer` явно исполняет
  `ScriptEngine.executeScript(MASTER_HANDLER_FILE)` — `MasterHandler.main()` регистрирует
  все хендлеры; новые классы попадают туда через секции admin/voiced. Компиляция — на старте
  GS (javac, sourcepath `data/scripts`).
- Регистрация у менеджера идёт через bypass `OlympiadNoble 4/1` (класс ядра
  `entity.actor.instance.OlympiadManager`); команда использует тот же публичный API
  `Olympiad.registerNoble(player, false)` — AntiFeed/Dualbox и прочая логика не задеты.

## Сборка и верификация (без запуска сервера)

- Ядро: `javac` (LibericaJDK 25) против `libs\GameServer.jar` — без ошибок; класс подменён в JAR
  (`jar uf`, только внешний класс; вложенный `$SingletonHolder` не менялся); декомпиляция из
  обновлённого JAR подтверждает гейт `_oly_reg\_verify_out`.
- Скрипты: `javac` всего дерева `data\scripts\handlers` (420 файлов) против JAR — без ошибок
  (`_oly_reg\scriptbuild`).
- Бэкап ядра: `_oly_reg\GameServer.jar.pre-olyreg` (откат — вернуть файл в `libs\GameServer.jar`
  при остановленном GS). Исходник патча: `_oly_reg\src\...`.

## Проверка в игре (для администратора)

1. Ноблес вне менеджера: `/oly` и `//oly` и `.oly` — системное сообщение о регистрации в
   1v1 class-irrelevant; `oly status` — очки/период/лист ожидания.
2. Не-ноблес: отказ ядра «Only Noblesse can participate…».
3. Ноблес с сабклассом активным: отказ ядра.
4. `oly cancel` до подбора матча — снятие с листа; после назначения в матч — отказ ядра.
5. Период олимпиады закрыт (ночь) — отказ ядра.
6. Обычный чат с текстом `/привет` — не должен перехватываться (уходит в broadcast как раньше);
   `//command` ГМ-команды ГМов работают как раньше.

# 87. Неуязвимый дальник, повторный сон под root и root-снятие раньше Bluff

База: `adb61119c6c7d5da4bdff4600ad1c259c60f1c80` (86). Резервная ветка: `backup/before-invulnerable-ranged-root-priorities-87-2026-10-21`.

## Что исправлено

### 1. Неуязвимая дальнобойная цель

Раньше document84 обещал запрет атак, но `act` допускал DAMAGE по неуязвимому дальнику, а физического бота мог возвращать родительской автоатаке. Теперь:

- Любой бот не выбирает атакующие/контролирующие/дебаффающие навыки по `enemy.isInvul()`; физический fallback не передаётся родительскому движку. Повторная проверка есть в общем фильтре навыков и native событиях управляемых аренных ботов.
- **Мили против неуязвимого дальника:** обычный MOVE_TO к цели, до физической дальности с учётом коллизий → ожидание без атаки. Если цель уходит, бот пробует сблизиться снова. При root/CC/недоступном пути — ожидание без обхода ограничений.
- **Дальник против неуязвимого дальника:** без атаки, с попыткой обычного кайта в существующем круге450. Отдельного параметра600u от врага нет. Это явное новое исключение и для Cardinal под собственным барьером.
- Реальное снятие неуязвимости освобождает только свой маршрут/lease и восстанавливает прежнее управление. Если идёт настоящий каст, cleanup ждёт его окончания. Обычная атака затем возобновляется только по штатным условиям боя, а не принудительно.
- Допустимая self-поддержка и готовые453/1510 сохраняются перед движением. Существующий питомец не получает новых attack-команд по invul; прежнее ATTACK-намерение останавливается до проверки3с cadence. Уже выполняющийся настоящий каст питомца не прерывается.

Новая фаза **обязательна** в обоих аренных драйверах `BotManager` и общем `BotTactics.tick` тренировки, раньше Bluff и обычной атаки; не зависит от опционального TacticalAI в этих путях. В самом обычном `act` есть повторный вход. Против **неуязвимого мили** сохранён существующий `tickInvulnerableMelee` с прежними исключениями Cardinal/root. UD/Vengeance/760 не подменяются invul: правило86 для пары танков остаётся.

### 2. Rooted Dominator115 после пробуждения защищённого танка

Ранее `tankSleepPriority` работал только при `movingSupport`, поэтому при root обещанный1097 мог отсутствовать в старом override и уступать обычной ротации. Теперь ready-приоритет действует для `movingSupport || rootedKite`:

- после действительного пробуждения танка под активным110/368/760 — реально изученный готовый1097 с текущего места;
- старый rotation override без1097 и generic `nextDecision`/reaction больше не задерживают законную попытку;
- настоящий сон цели сохраняет HOLD; новый cast не дублируется во время настоящего каста/pending;
- native MP/reuse/range/LOS/silence/CC/conditions/failure backoff, иммунитет цели и фиксированные20% успеха сохранены. «Готов» не означает гарантированное засыпание.

### 3. Escape Shackle453 важнее собственной фазы Bluff

Для93/101/108 удалён явный отказ из-за собственного358-STUN на враге. При root законно доступный SELF453 проверяется до Bluff-маршрута и обычного decision-таймера; `BluffRear.skillAllowed` допускает только это специальное SELF453-исключение. Другой настоящий каст/pending не прерывается; reuse/MP/physical mute/native условия не обходятся. Если453 недоступен, root не разрешает двигаться или бить спереди во время Bluff. Фактическое снятие root определяется родным эффектом453, не ручным удалением флагов.

1510 остаётся магическим ONE-self-cast для131 при root **или physical mute**: 2с cast,15с reuse,25+7MP. В87 меняется описание, не баланс/эффект1510.

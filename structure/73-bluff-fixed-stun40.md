# 73. Bluff: строго фиксированный шанс стана 40%

## 1. Область изменения

У Bluff (ID358) шанс **продолжительного эффекта Stun — 40%** на каждую допустимую попытку применения. Это общий native XML: действует для игроков и ботов, включая Adventurer93, Wind Rider101 и Ghost Hunter108, обычный уровень1 и Chance101–115.

Не изменены:
- независимые мгновенные эффекты Bluff (разворот), TargetCancel и DeleteHateOfMe: у каждого прежний параметр `chance=80`;
- базовый откат12000мс (+50% из70), длительность стана9с, MP35, дальность и условия DAGGER/DUALDAGGER;
- маршрут за спину и удары только умениями со спины из72, без автоатаки;
- Trance1394 Cardinal97 и Dreaming Spirit1097 Dominator115: фикс20%; Fear1092:15%; правила собственного/пассивного Celestial;
- экипировка full epic+6, локальный ipconfig, БД, JAR и существующие core-патчи.

## 2. Почему именно фиксированные40%

В `game/data/stats/skills/00300-00399.xml`, **только у358**, добавлены:

```xml
<activateRate>40</activateRate>
<minChance>40</minChance>
<maxChance>40</maxChance>
```

Native `Formulas.calcEffectSuccess` учитывает параметры/резисты, затем ограничивает итог между minChance/maxChance. При40/40 итоговый бросок имеет40 успешных значений из100. Уровень, MEN, эпик, vulnerability и положительные/отрицательные множители не повышают и не понижают этот шанс для обычной допустимой попытки. Полная невосприимчивость к дебаффам или trait по-прежнему блокирует эффект: фиксированный шанс не пробивает иммунитеты, не обходит защиту от повторного обновления активного контроля и не гарантирует успешный каст при нарушенных условиях.

Исходный activateRate40 и таблица Chance42…70 оставлены нетронутыми. Они все ниже100, поэтому не включают гарантированный fast path ядра, а итоговый clamp40/40 перекрывает их численное повышение. Заточка сохраняется как родной маршрут и уровень, но **больше не повышает шанс стана**.

`Skill.applyEffects` проверяет продолжительный Stun независимо от мгновенных80%-эффектов. Здесь нет зависимости «сначала80%, затем40%» и нет итоговых32%. Сам Stun-хендлер второго броска не делает.

В `BotControlChance.apply` для93/101/108 добавлена очистка старой регистрации `FIXED_DEBUFF_RATE_PLAYERS`, которая могла бы вернуть общий ранний25%-gate до проверки min/max. Очистка при спавне/регистрации уже существовала; теперь она повторяется и в тактическом тике. Общий процент ядра не меняется. Для Bluff не создаётся private-копия: игрок и бот используют один native Skill со всеми родными условиями.

## 4. Проверки

Команды из корня репозитория:

```bash
python tests/fakeplayersai/dominator_pressure_bluff_tests.py
python tests/fakeplayersai/passive_barrier_bluff_tests.py
```

Первая проверка: **8316 PASS-проверок**, все custom/effect scripts компилируются. Использованы настоящие SkillData, Formulas и Skill.applyEffects установленного в репозитории GameServer.jar:
- все16 уровней358 проверяются на min=max40, отсутствие fast path и сохранённые reuse/длительность/MP;
- репрезентативные1/101/108/115: три dagger-класса, оба типа арен, игрок/бот с обеих сторон; нормальные, резко повышенные и пониженные trait/vulnerability; по2000 бросков на профиль, статистический допуск вокруг40%;
- устаревший общий gate намеренно выставлен в100%: dagger-бот снимает регистрацию и возвращается к40%, без изменения самого глобального процента в production;
- полная debuff/trait immunity остаётся0%;
- по4000 реальных применений `Skill.applyEffects` у1 и115 подтверждают около40% попаданий единственного continuous Stun. В этой отдельной fixture мгновенные действия отключены, а EffectList фиксирует результат без планировщика мира; XML-инвариант отдельно подтверждает неизменные независимые80%-эффекты.

Сетевые пакеты, БД и запуск world scheduler изолированы тестовыми заглушками; формула, загрузка native шаблонов, условия применения continuous-эффекта не подменены. Это не тест на работающем сервере пользователя и не обещание ровно40 попаданий на любые100 кастов.

Полный набор регрессий также прошёл:1197 /6912 /26353 /1628 /4068 /7615 /61 проверок. Включены собственный/пассивный барьер, фикс20% сна, Clarity, настоящий PlayerAI с маршрутом Bluff у края, удары только со спины, full epic+6 Cardinal, все19 классов и защитные приоритеты. Custom/effect scripts компилируются; исходные JAR и БД не изменены.

## 5. Установка и откат

Обновление GitHub не копирует файлы в `C:\EpilogueServer`. Прямого доступа к установленному серверу пользователя нет; живой GameServer здесь не перезапускался.

Для применения скопировать из актуальной main, сохраняя пути:
1. `game/data/stats/skills/00300-00399.xml`;
2. `game/data/scripts/custom/fakeplayersai/BotControlChance.java`.

Затем выполнить **полный перезапуск GameServer**, чтобы перечитать SkillData и перекомпилировать скрипты. Не ограничиваться reload ботов. Если предыдущие обновления ещё не установлены, сначала обновить весь согласованный набор файлов согласно72/71/70/69/68; эти два файла не заменяют предыдущие изменения AI.

# 24. Тренировка: вход, селфбафы, финальное восстановление и свободный возврат

Актуализирует тренировочные правила документов [20](20-olympiad-suite-and-giran-services.md), [21](21-strong-tempo-and-training-fixes.md), [22](22-class-skills-openers-and-training-results.md). Рейтинговая Олимпиада и ограниченный Fear из документа23 этим изменением не перенастраиваются.

## Что изменено

1. **Нет минимального HP, CP или MP для регистрации.** Персонаж должен быть живым, не в бою/касте, без саммона, группы, торговли, другого инстанса, текущей/начинающейся дуэли, регистрации Олимпиады и прочих несовместимых состояний. Низкие ресурсы не должны скрывать уже запущенную подготовку дуэли: проверяется реальное приватное поле `_startingDuel`, несовместимое ядро отклоняет вход безопасно.
2. После записи recovery-журнала, при входе **снимаются прежние бафы и дебафы обоих участников**. Старые эффекты не сохраняются для последующего восстановления. Предметы, заточка, уровень и изученные навыки человека не меняются.
3. Вход также заполняет HP/CP/MP, чтобы реальный `DuelManager.canDuel` и его последующий снимок не сохранили низкие ресурсы. Это не требование к игроку прийти с полным здоровьем. Откаты на входе отдельно не сбрасываются.
4. После штатного запуска дуэли (~6с) выдаются **13 базовых олимпийских бафов + отфильтрованный профиль бойца/мага**, без CoV/аналогов, танцев/песен, преждевременной защиты танкового пула и коротких opener-усилений.
5. Во время подготовки бот **действительно кастует** разрешённые изученные селфбафы своего эффективного пресета: обычные условия, расход, анимация и время каста. Повторный тик не прерывает каст. Короткие Final Secret/Wind Riding/Enlightenment и аналоги остаются отдельным однократным предбоевым этапом примерно за3с; UD-пул сохраняется для боя. Подготовка не тратится на создание стрел/костей и бессмысленное повторное лечение.
6. По умолчанию подготовка **10с** (`TrainingPreparationSeconds`, диапазон10–60). За последнюю секунду закрывается допуск **новых** кастов. Уже начатые касты обоих участников завершаются, не обрываются. Затем **один раз обоим** заполняются HP/CP/MP и сбрасываются обе реальные карты откатов умений (`resetDisabledSkills`, `resetTimeStamps`), отправляется `SkillCoolTime`. После этого выдерживается **новая защищённая секунда** до фактического старта. Если текущий каст/предбоевое усиление задержал этап, старт отодвигается, а не запускается с неполными ресурсами.
7. При завершении/выходе отдельного нового сброса откатов, снятия эффектов или лечения нет. Сама штатная дуэль при нормальном завершении восстанавливает свой внутренний снимок ресурсов/дуэльных дебафов — это существующая семантика ядра, не дополнительная услуга тренера.

## Новая локация и важное ограничение расстояния

| Участник | Точные координаты |
|---|---|
| Бот | `44112,188116,-3513` |
| Игрок | `42705,188869,-3513` |

Личная непубличная копия порта Гирана. Рабочий центр скрипта `(43409,188493,-3513)`, радиус1000; координаты участников не подменены на более удобные.

**Расстояние между заданными точками ≈1595.83, а штатная дуэль отменяется при расстоянии между участниками свыше1600.** Поэтому отход от соперника уже в начале может завершить дуэль. Скрипт не меняет этот лимит ядра, не удерживает человека искусственным стопом и не подделывает дуэльные флаги. Для более просторного боя нужны согласованные более близкие стартовые точки либо отдельная доработка ядра. Без геодаты этот перенос не создаёт стены.

### Почему нужен TrainingPeaceZones

Точки пересекают `giran_port3` и `giran_port4` из `data/zones/peace.xml`. В данном ядре частный `Instance` сам по себе **не исключает географические зоны**: обычная дуэль там запрещена.

`TrainingPeaceZones.java` устанавливает делегирующие адаптеры **только этих двух реальных PeaceZone**, сохраняя исходные геометрию, настройки, слушателей и учёт участников. Только явно зарегистрированный положительный ID созданного тренировочного инстанса пропускает мирное членство. Обычный мир, чужие инстансы и остальные зоны используют исходное поведение. XML порта, общий PvP-режим, JAR и прямые zone-флаги персонажей не меняются.

- Установка проверяет реальную структуру и публичный API ядра, заменяет ссылки class/region-map через compare-and-replace; неполная установка откатывает уже заменённые ссылки.
- Инстанс регистрируется **до спавна/телепорта**; проверка полномочий выполняется при обслуживании тренировки. Запретные фактические zone-флаги остаются причиной безопасной остановки.
- Утеря ссылок (например, reload зон) отзывает разрешения и закрывает допуск. **Не перезагружать зоны/скрипты при активных тренировках.** Завершить возвраты, затем перезапускать GameServer согласованно. Без общего reload-lock ядра нельзя обещать атомарность относительно произвольной GM-перезагрузки.
- Разрешение снимается после подтверждённого возврата человека и удаления инстанса, не посреди исходящего телепорта.

## Исправление рывков после боя

Причина в прежнем обработчике: пока ждал завершения ядровой дуэли, он каждые100мс вызывал остановку человека. Теперь переход к остановке выполняется **однократно**, без постоянных `stopMove/abortCast/Idle` во время ожидания. Снимается принадлежащая подготовке immobilized-блокировка, когда это безопасно.

`PlayerAI` дополнительно хранит отложенное движение `_savedMoveTo`; простой `Idle/Active` его не очищает. Однократная синхронизация после подтверждённого обратного телепорта очищает отложенные действия через настоящий `notifyActionCancel`, только если человек ещё не начал новое движение/бой/каст и не получил новый контроль. Recovery-журнал отмечает эту фазу, чтобы повторный reaper/ошибка удаления бота **не сбрасывали новые действия/эффекты игрока**. Фаза `humanReturned` по-прежнему означает только GC бота, без изменений человека.

Выход `.training leave` не убивает бота и не приписывает ему победу. Ядро не предоставляет безопасной отмены уже поставленных задач старта/конца дуэли; возврат ждёт их завершения — вплоть до остатка общего лимита120с. Принудительная отмена по истекшим «нескольким секундам» не добавлена.

## Как пользоваться и установить

1. В Гиране у **Olympiad Trainer** выбрать класс и сложность → **Начать тренировку**. Долечиваться заранее не требуется; прежние эффекты при входе будут сняты.
2. Дождаться запуска дуэли и выдачи стартового набора. Наложить свои селфбафы в подготовительные10с. В финальную секунду новые касты не принимаются; дождаться сообщения о полном восстановлении и старте.
3. Выход/статус/отчёт: `.training leave`, `.training status`, `.training report`. Повтор — снова у тренера. Бот85уровня использует те же настройки экипировки и заточки навыков, что рейтинговый.
4. **Установка администратором:** сначала завершить тренировки/возвраты, сохранить живую БД и локальные настройки, остановить GameServer; обновить все изменённые Java-файлы вместе, включая **новый TrainingPeaceZones.java**, перезапустить. JAR/клиент/DDL этот пакет не заменяет. Не удалять `data/training-arena-recovery`, `.account-lock`, незавершённые журналы.
5. Локальный `git pull --ff-only` допустим при чистой `main`; при локальных правках сначала сохранить их, не применять `reset --hard` вслепую. Публикация на GitHub сама по себе не обновляет уже работающий Windows-сервер.

### Проверка

```
python tests/fakeplayersai/suite_tests.py
```

Офлайн-проверки включают компиляцию против поставленных JAR, реальные API/Skill-метаданные и изолированные модели переходов. Дополнительные регрессии этого обновления: 513 тренировочных/core/журнальных проверок, 2661 проверка реальных классов зон из JAR, 41 проверка допуска селфбафов с настоящим Skill и 68 изолированных проверок подготовительного запроса. Негативные тесты потери ссылок намеренно пишут SEVERE и проверяют безопасный отказ. Это **не live-тест GameServer/MySQL/клиента**. После установки проверить: вход с почти пустыми ресурсами; снятие прежних эффектов; обе точные позиции; отсутствие мирного флага в личной копии и сохранение его в обычном порту; реальные касты бота; последний безопасный reset обоих и1с задержку; нормальную победу/поражение; выход/разрыв соединения; свободный бег без периодического стопа после возврата; восстановление при ошибке БД/перезапуске.

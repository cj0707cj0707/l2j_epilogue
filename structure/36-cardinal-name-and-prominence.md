# 36. Кардинал: имя без цифр и дополнительный Prominence

## Причины

1. Общий генератор имён выдавал `Cardinal2`, `Cardinal3` и т.д., когда базовое имя занято. При восстановлении бот с собственным суффиксом снова проходил поиск: его текущее имя считалось занятым, поэтому происходило новое переименование. Конкретный состав живой БД здесь не проверялся: нельзя утверждать, кто занимает `Cardinal` на машине пользователя.
2. `1230 Prominence` был в ротации97, но отсутствует в штатном дереве Bishop/Cardinal. Одного добавления ID в массив недостаточно: `BotTactics` берёт только `getKnownSkill`, а `giveAvailableSkills` не выдаёт чужие классовые навыки.
3. Старое исключение для Prominence/Mana Burn обходило только первый фильтр сна. Затем `protectedSleep` вновь запрещал оба навыка через `TacticsPolicy.allowed`.
4. Ограничитель10с был только запретом раннего каста: готовый Prominence всё ещё мог проиграть случайному выбору других навыков или кайтингу.

## Исправление имён

Только для класса97 генератор сначала пробует `Cardinal`, затем `CardinalA`, `CardinalB`, …, `CardinalAA` и т.д. Имена без цифр, в лимите клиента16символов; поиск ограничен4097 кандидатами. При исчерпании — отказ с явной ошибкой, а не случайное конфликтующее имя.

`CharInfoTable.getIdByName` проверяет владельца имени без учёта регистра. Имя разрешено, если свободно или принадлежит **этому же objectId**. Поэтому `Cardinal26` переименуется при регистрации, а новое имя не будет увеличивать суффикс на каждом рестарте. Если каноническое имя занято другим персонажем, он не удаляется и не переименовывается; используется буквенный вариант. У остальных классов прежний генератор не изменён.

Переименование использует существующие `Player.setName`/`storeMe` до входа бота в мир. ObjectId, аккаунт, предметы, класс, олимпийские очки и связи персонажа не заменяются. Дополнительно актуальное имя сохраняется в `REGISTRY_NAMES`, чтобы последующее сохранение реестра после despawn не возвращало старую строку имени. Ручное редактирование таблицы `characters` не требуется.

## Выдача и использование Prominence

`BotSpawner.applyBotOnlySkills(player,preset)` явно выдаёт1230 максимального обычного уровня **28** (определяется через настоящий `SkillData.getMaxLevel`). Только при клиенте `null`, фактическом классе97 и пресете97. Уже изученная/заточенная версия не заменяется; повторный вызов ничего не добавляет. При отсутствующем шаблоне — предупреждение без добавления `null`.

Вызывается в трёх bot-only путях:
- создание постоянного бота после штатных классовых навыков;
- регистрация/восстановление постоянного бота после `applyClassSkills`, перед общей заточкой;
- создание временного тренировочного бота после штатных навыков, перед общей заточкой.

Базовая выдача — `addSkill(skill,false)`, без отдельной SQL-выдачи. Затем действует существующая общая политика заточки ботов: она может повысить/сохранить навык штатным `applySkillEnchants`. После `Player.load` отсутствующий навык снова выдаётся bot-only путём. **Деревья навыков людей, глобальный XML1230 и ядро не менялись.** Человеческий Кардинал от этого не получает Prominence; подготовка человеческого участника тренировки метод не вызывает.

### Интервал10 секунд в тактическом бою

Для **Олимпиады при включённой тактике и изолированных тренировок** действует `TacticsPolicy.CardinalProminence`:
- первый каст — при первой законной возможности;
- следующий запрос не раньше10 000мс после принятого `useMagic`;
- отклонённый `useMagic` не расходует10секунд, штатный failure-backoff сохраняется;
- когда срок наступил и1230 находится среди законных вариантов, он выбирается без случайного проигрыша другой обычной атаке и не откладывается ради планового кайтинга;
- срочное лечение/защита и готовый высокоприоритетный interrupt сохраняют приоритет;
- при смене матча/пары существующий `prepare` сбрасывает часы;
- оба фильтра сна согласованы: исключение только для1230/1398 Кардинала, а не для всех навыков/классов. Реальное заклинание может разбудить цель по обычным правилам ядра.

Это **не безусловный таймер урона**: MP, LOS, дальность, native reuse, mute/стан, уже исполняемый каст, законность цели, условия ядра и интервал реакций остаются. Если каст на10-й секунде невозможен, он ждёт законной возможности, не телепортирует/не восстанавливает ресурсы/не отменяет другой каст. Явный override ротации без1230 сохраняется: скрытого принудительного возврата ID в override нет. Обычный мировой AutoUse вне тактической Олимпиады/тренировки этим планировщиком не заменяется; глобальный reuse1230 (для всех игроков) не увеличен до10с.

## Проверки и применение

```bash
python tests/fakeplayersai/cardinal_name_prominence_tests.py
python tests/fakeplayersai/character_login_skill_data_tests.py
python tests/fakeplayersai/suite_tests.py
```

Требуются Python и JDK25 (для login/XML регрессии также lxml). Новая регрессия прошла **8524 проверки**:4097 уникальных буквенных кандидатов/исчерпание, занятие чужим/своим ID и50 повторных загрузок без роста суффикса; настоящий1230/28, сохранение реальной заточки101, отказ людям/другим классам; многократные10с-циклы, отказ/сброс, срочное восстановление, ограничения сна иnative legality. Production-скрипты скомпилированы против настоящих JAR.

Login/XML регрессия также прошла:82 XML/XSD,619 ссылок,99 восстановленных определений/397 базовых шаблонов,412 выборок. `run_bot_combat_tests.py` прошёл. Полный suite, как и до этого изменения, остановился в прежнем `tactics_tests.py` на ожидании18 пресетов/старого текстового формата (`audit must cover the full eighteen-class roster`); последующие проверки не запускались. Это не полный зелёный suite. Новая проверка выполняет production-методы и реальный API ядра, но не полный живой планировщик боя/пакеты клиента/БД.

Для применения дождаться возврата тренировочных игроков, остановить GameServer, обновить изменённые скрипты и перезапустить штатным загрузчиком. Постоянный Кардинал переименуется и получит навык при регистрации; новая тренировка создаст бота уже с навыком. Не сбрасывать реестр/персонажей и не менять XML или БД вручную.

Живая приёмка: имя без цифр и без нового суффикса после повторного запуска; чужой `Cardinal` сохранён; в логе выдача `bot-only ... Prominence28 granted`; в бою1230 на первой законной возможности и далее с интервалом не менее10с между принятыми запросами, в том числе после Trance. Проверить MP/LOS/mute/недальность и срочный хил: ограничения не обходятся. На Windows/живом сервере это ещё не проверено.

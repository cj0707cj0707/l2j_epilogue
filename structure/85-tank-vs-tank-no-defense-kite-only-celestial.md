# 85. Танк против танка: без кайта по UD/Vengeance, с прежней реакцией на неуязвимость

> **Статус после86:** правило реализовано в исходниках, а не только описано. Полная карта файлов, экипировка+10 и установка — [86](86-tank-mirror-no-defense-kite-and-all-gear10.md).

## Правило

- Бот-танк продолжает обычный бой с танком под активными110/368/760 (UD/Vengeance/аналогичная краткая защита).
- Настоящая `enemy.isInvul()` не отменяется: прежний кайт от мили-противника сохраняется независимо от класса бота.
- Для ботов не-танков реакция на защищённого танка прежняя.
- Работает в олимпиаде и тренировке, против бота или игрока. Управление человеком не меняется.

## Где реализовано

`game/data/scripts/custom/fakeplayersai/BotTactics.java`:

```java
private static boolean requiresInvulnerableKite(Player bot, Player enemy)
{
    return (enemy.isInvul() && meleeOpponent(enemy))
        || (TankClassMechanics.defendedTank(enemy) && !TankClassMechanics.tank(bot));
}
```

Эта **одна** проверка вызывается из `tickInvulnerableMelee`, `invulnerableMelee` и `act`. Ранее предложенная в этом документе замена только `required` в первом методе была недостаточна: два оставшихся пути могли снова включить кайт.

`TankClassMechanics.java` без изменений: `tank` определяет семейства Paladin/Dark Avenger/Temple Knight/Shillien Knight и их продолжения; `defendedTank` требует реально действующий BuffInfo110/368/760. Проверка защита/класс не заменяется оружием, анимацией или заявкой на каст.

При окончании настоящей неуязвимости старая аренда кайта освобождается, даже если UD ещё действует. Настоящий каст не прерывается; сохранённый маршрут очищается после его окончания, без потери ссылки на маршрут во время каста.

Для зеркальных боёв проверяется отсутствие кайта, его сохранение под настоящей неуязвимостью и прекращение после неё при оставшемся UD. Отдельно проверен атакующий путь `act`.

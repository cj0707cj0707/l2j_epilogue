В активном конфиге броня уже была10, но Java fallback оставался6. Бижутерия была6. Теперь оба источника согласованы. Набор бижутерии не меняется: Queen Ant6660, Baium6658, Zaken6659, Valakas6657, Antharas6656, в том числе у Cardinal.

Новые боты получают значения через общий `BotSpawner.equipGear`, включая тренировочные экземпляры. У загруженных изБД ботов `BotManager.registerBot` после входа в мир вызывает `ensurePresetGear`, который теперь дополнительно применяет текущую заточку через `reenchantGear`. Уже правильные вещи не перезаписываются. Изменение заточки выполняется на существующих предметах, с обычным обновлениемБД и пакетов; специально ради заточки оружие/броня не пересоздаются. Существующая отдельная проверка комплекта по-прежнему может переснарядить бота, если комплект отсутствует/непригоден.

## 2. На кого действовало управление через меню .bot

Backend кнопок меню — `handlers/chat/commands/admin/AdminBot.java`, команды `encharmor`, `enchweapon`, `enchjewel`, `reenchant`.

**Обнаружено:** общий обработчик обходил только `BotManager.getBots()`. Это весь основной реестр, в том числе обычные/олимпийские/заказные боты, но тренировочные боты намеренно живут отдельно в `TrainingArena.SESSIONS/BOTS` и не попадали в этот обход.

**Исправлено:** к основному реестру добавляется snapshot онлайн clientless-ботов текущих незакрытых тренировочных сессий. Объединение по objectId исключает двойную обработку. Игроки, офлайн-акторы и закрытые/удалённые тренировочные экземпляры не включаются. Значения не захардкожены в обработчике: последующее изменение через меню продолжает работать для всех19 профессий. Категории независимы: броня не меняет оружие/бижутерию и наоборот.

Офлайн-персонажи не обходятся напрямую SQL-командой: основной пул подхватывает сохранённые настройки при следующей загрузке; новые тренировки — при создании. Инвентарь человека, участвующего в тренировке, не затрагивается.

В тесте вызван **тот же application-метод AdminBot**, который используют эти четыре ветки меню. Живой ввод `.bot`, клиентский HTML и права аккаунта не проверялись; новые алиасы/изменения прав не добавлялись. Другие кнопки меню (spawn, skill-enchant, перемещение и т.п.) в78 не расширялись на отдельный тренировочный реестр.

## 3. Cardinal без собственного Celestial Shield

Для clientless-бота Cardinal97 запрещён автоматический каст собственного `1418`:

- удалён из принудительного survival-пула и обоих fallback-выборов;
- отфильтрован из эффективной ротации, автонавыков и автобаффов, даже если его сохранили старые overrides;
- shared `tacticalSkillAllowed` и синхронный native `OnCreatureSkillUse` guard запрещают обход другим автоматическим путём.

Навык не удаляется из SkillData/XML или книги класса и у игроков не меняется. Чужой/уже существующий эффект1418 не снимается принудительно. Случайная пассивная защита655→5576 остаётся; её длительность, неотменяемость от действий и шанс не менялись. Под реально действующей неуязвимостью Cardinal по-прежнему не кайтит.

## 4. HP Cardinal строго ниже75%: сначала самолечение

Если `currentHP < maxHP * .75` и изученный **Greater Battle Heal1218** законно доступен, он получает приоритет над Trance, Prominence и движением. Никакого округления отображаемого процента:74.99% — приоритет лечения, ровно75% — уже обычная ротация.

- Работает против всех19 классов, человека/бота, в тренировке/олимпиаде, с Clarity или без неё, включая сон/неуязвимость противника.
- Кандидат1218 добавляется из реально изученных навыков независимо от сохранённого списка ротации/баффов; цель — сам Cardinal.
- Используется обычная self-support ветка тактики, учёт pending, native `useMagic`, resources/reuse/condition и failure-backoff; фактический каст не заменяется прямым добавлениемHP.
- Движение останавливается для лечения; уже идущий настоящий каст или pending не прерываются и не дублируются. Приоритет пересчитывается после завершения предыдущего действия и существующего восстановления MP Cardinal.
- Недоступный хил не форсируется: при cooldown, silence/CC, native запрете или отсутствии навыка остаётся законный fallback. **Прежний общий запрет самолечения ботов под неуязвимостью сохранён**, включая проверки на применении эффекта. Поэтому под5576 при недоступном лечении Cardinal продолжает доступный Trance, а не бесполезный хил и не кайт. Это не новая возможность лечиться сквозь invulnerability.
- При HP>=75% прежние правила сохранены: готовый Trance, кроме разрешённого76 готового Prominence приHP строго>90%. Само лечение приHP>=75% не запрещено, если его выбирает обычный fallback.

Сохранены:20% Trance/Dreaming Spirit,40% стан Bluff,12с его базовый reuse, Prominence приHP>90% с10-секундным интервалом, запрет будить спящую цель,210с боя, свободное мили-преследование из77 и зона самого кайта.

## Установка

Обновить в установленном сервере конфиг и все8 runtime Java-файлов из таблицы, затем полностью перезапустить GameServer через существующий launcher. В конфиге должны быть `EnchantArmor=10`, `EnchantJewel=10`, `EnchantWeapon=16`. Не заменять прочие личные параметры без необходимости.

Основной пул применит заточку при загрузке; тренировочные боты — при создании, а уже работающие экземпляры после изменения через меню/`reenchant` обработчик. Для отката имеется резервная ветка. Доступа к установленному `C:\EpilogueServer` в этой сессии нет: изменение GitHub не означает автоматическое копирование/перезапуск локальной установки.

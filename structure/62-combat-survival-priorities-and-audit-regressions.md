# 62. Приоритет выживания, root Berserker и ограниченные попытки контроля

База: `c360102ae2b1ce3a5b3a002d08ce4ec8c42a67dc` (61). Выполнены только пункты **1, 3, 4, 5, 9, 12** аудита. Изменяется код репозитория, не работающий GameServer. Правила действуют в тренировке и на Олимпиаде, кроме отдельного исправления ranked-драйвера Berserker.

## Порядок решений

1. Уже идущий настоящий каст не прерывается; собственные stun/sleep/fear, полный skill-lock и native silence остаются ограничениями.
2. Прежние срочные Soul Cleanse/ Escape Shackle проверяются раньше обычного решения. Цель самолечения сохраняется до завершения каста.
3. **Перед обязательным кайтом защищённого противника, отходом после собственного сна и отходом Dominator после собственного root/Hammer stun** рассматриваются только законные спасательные self-умения: срочное HP-лечение, разрешённый CP и защитные навыки.
4. Если спасательного каста нет (откат, недостаток ресурсов, запрет, нет нужного эффекта/заряда), управление немедленно возвращается прежнему маршруту. После лечения маршрут продолжается; атаки не подменяют обязательный кайт.
5. После окончания причины отхода возвращаются обычные классовые правила.

Это контекстные решения, а не обучение на игроках. Координаты, геоданные, радиусы, частота flank и случайные шансы не изменены.

### Спасательные умения

Используется тот же генератор полностью законных кандидатов, что и для обычного боя: настоящий MP/HP-cost, native reuse, `Skill.checkCondition`, CC/mute, цель и backoff. Для HP-лечения перед движением общий порог **HP<65%**, дополнительно сохраняются более строгие прежние классовые ограничения (например, Body Reconstruction≤40%). Защитные умения сохраняют прежний скоринг; готовые Flame/Angelic сохраняют свой порядок. Под действующими иконами Sacrifice запрещён.

CP Dominator: обычный порог<50%; под собственным melee root/Hammer stun разрешено восстановление приCP≤85%. Сохранено чередование CP→доступная атака: спасательная вставка не обнуляет долг атаки и не создаёт новый бесконечный CP-цикл. В ограниченном режиме противника по-прежнему разрешены только Steal Essence и CP.

Во время спасательной вставки запрещены самообездвиживающие УД/Vengeance и подготовительные seed-касты784/761/788; они не должны мешать выходу из опасности. Это не общий запрет этих навыков. Активный собственный Celestial сохраняется движением без нового каста. Под3282 на противнике Cardinal сохраняет четырёхскилловый whitelist из59.

### Berserker под root

`BotManager.driveBerserkerStep` больше не приравнивает запрет движения к запрету всех действий. После недоступного Soul Cleanse он передаёт rooted-решение в общий `BotTactics.tickRootedBerserker`: доступны реальные неподвижные умения, включая833 при допустимомHP. Rush/другое движение по-прежнему блокируются native-проверками. Постоянное владение legacy-драйвером не передаётся BotTactics.

Существующая фаза Rush при действующем native STUN сохранена: `RushStunSupport.stun` проверяет реальный текущий эффект STUN, без ограничения на793 или кастера. Пока фаза активна, правило «только повтор Rush» не заменяется ротацией; Soul Cleanse проверяется прежним ранним путём. После снятия root продолжается прежний ranked-драйвер.

### Dominator: запрос не равен наложенному контролю

- За один цикл не более **двух реальных запросов** opener-контроля, включая отказанные/прерванные попытки. Временный отказ дополнительно ограничивается прежним backoff. Недоступный контроль не блокирует доступные проклятия/урон.
- Успешный opener отмечается только по **действующему собственному эффекту**, а не по `useMagic=true`, началу каста или появлению reuse.
- Завершение с резистом и исчерпание бюджета не считаются наложенным эффектом. После бюджета бот продолжает проклятия и атаку, а не бесконечно повторяет сон.
- Каждое проклятие тоже имеет максимум две попытки за цикл; оно отмечается наложенным только по собственному эффекту. Отказ/прерывание не выдаёт фиктивный успех.
- Следующий цикл открывается после подтверждённого выполнения атакующего действия, не одного начала каста. Для наблюдения используются собственный эффект, полный native debit initial+hit MP либо реальное событие direct damage от этого бота этой цели этим навыком. Это особенно важно при нулевой MP-стоимости под Maximum Clarity.
- MP-наблюдение — консервативный вспомогательный признак, а не новый API завершения каста: регенерация может скрыть debit. Начальная MP-стоимость, reuse и `sawCast` сами по себе фазу не продвигают. Попытки остаются ограниченными даже при неизвестном завершении.
- Наблюдатель direct damage живёт только на время одного pending-каста; снимается при отказе, разрешении pending, смене контекста, forget и TTL/лимитной очистке. Callback только записывает volatile-флаг, не берёт тактические/аналитические блокировки и не сохраняет pooled event.

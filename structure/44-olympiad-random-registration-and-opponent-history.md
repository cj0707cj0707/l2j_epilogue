## №1. Одна случайная регистрация

Новый `custom/fakeplayersai/OlympiadRegistration.java` обслуживает быстрый combat tick, maintenance ticker и кнопку администратора:

- Список ботов каждый проход перемешивается.
- Когда бот впервые обнаружен свободным и подходящим для очереди, назначается независимый срок **через5–20 секунд**. Следующие проходы используют тот же срок, не перебрасывают его и не обходят.
- При очереди/назначенном матче/арене, смерти, телепорте или отсутствии допуска pending-срок снимается; следующая подходящая свободная фаза получает новую задержку.
- Перед реальной регистрацией снова проверяются online/noble/alive, отсутствие клиента, gameId=-1, режим/стадион и native очередь. Люди этим путём не регистрируются и их очки не пополняются. Существующая bot-only доводка до OlympiadMinPoints сохранена, новых правил очков нет.
- Нажатие административной кнопки не обходит паузу. Один ограниченный отложенный follow-up через20с обслуживает запрос даже при отключённой автоматической регистрации; повторные нажатия не создают неограниченный набор таймеров. Возвращаемый счётчик кнопки — уже зарегистрированные, не ожидающие своей паузы боты.
- Проверки/регистрация сериализованы одним helper. Despawn/offline и исчезнувшие из roster ID очищаются. При отсутствии нужного core-helper автоматическая/административная bot-регистрация удерживается с SEVERE вместо незаметного запуска старого подбора.

Это сроки допуска, не обещание телепорта ровно через20с: добавляется native polling и ожидание свободной арены.

## №2. История и мягкий подбор

Новый core-helper `OlympiadDiversity` действует только на **настоящую бесклассовую очередь с явно зарегистрированным управляемым ботом**. Одного отсутствия клиента недостаточно. Классовые списки и очередь без таких ботов идут через сохранённый native matcher.

1. У каждого участника записываются **последние3 objectId соперников и последние2 профессии**. При выборе учитывается история обоих — как бота, так и человека.
2. Первым берётся дольше всех наблюдаемый в текущей очереди участник. Равные моменты разрешаются стабильно, чтобы readiness и выбор не противоречили друг другу; второй выбирается случайно среди одинаково подходящих кандидатов.
3. Сначала предпочтительны пары без недавних повторов ID/профессии. ID-повтор оценивается штрафом10 на сторону, повтор профессии —3; это предпочтения подбора, **не игровые очки**.
4. Если для ожидающего участника нет полностью новой пары, readiness ждёт до **20с с первого наблюдения в очереди**. Свежая альтернатива разрешает матч сразу. После порога выбирается минимальный суммарный штраф, равные варианты случайны. При двух оставшихся участниках повтор разрешается: бесконечного запрета пары нет. Общая задержка также зависит от native цикла/занятости арен.
5. Проверка ожидания подключена к `existNextOpponents`, а выбор — к `nextOpponents`. Нельзя передавать пустой результат конструктору только потому, что предпочтения ещё требуют ждать. Если очередь изменилась между проверкой и выбором, helper заново выбирает доступную пару; исходное native поведение при фактическом количестве<2 сохранено.
6. История записывается при **назначении пары**, не после результата. Отменённый позднее матч тоже может временно учитываться. Данные только в памяти, TTL2ч, максимум8192 историй; roster хранит слабые ссылки. После перезапуска история начинается заново. Нет записи в БД.

В смешанной очереди новый выбор учитывает всех кандидатов; это не резервирование ботов только для людей. Бот–бот и человек–бот получают ту же защиту от повторов. Состав пула, профессии персонажей и их количество не меняются. Это **не** вариант№3 с равной вероятностью каждой профессии: несколько одинаковых классов могут оставаться в пуле, но недавние профессии получают меньший приоритет. Пока классы заняты на других аренах, заставить их немедленно появиться в очереди невозможно.

## Минимальный core-патч и установка

`game/core-patches/olympiad-diversity/` содержит helper и `InstallOlympiadDiversity.java` (Java25 JDK). Меняются только два метода `OlympiadManager`: исходные тела сохраняются под `diversityOriginal…`, добавляются обёртки. Все прочие JAR entries, включая ранее установленные debuff/boundary guards, проверяются на неизменность.

Установщик принимает проверенный arena/debuff core, закрепляет helper sources и полный payload, пишет проверенный backup `.pre-olympiad-diversity-<hash>`, выполняет atomic replace при закрытых JAR handles. Неизвестный/повреждённый вход или несовпадение исходников/marker/payload останавливает установку. Повторный запуск только проверяет и не переписывает файл. Старые два установщика при наличии нового marker делегируют проверку итогового комплекта новому; без этого старый full-payload verifier ошибочно считал бы добавленные классы повреждением.

**На остановленном GameServer:**

1. Сохранить текущие custom-скрипты, launchers, core-patches и локальный `libs/GameServer.jar`.
2. Обновить `BotManager.java`, добавить `OlympiadRegistration.java`; скопировать согласованную папку `game/core-patches/` целиком и обновить `game/InstallDebuffGuard.cmd`, `game/GameServerTask.sh`.
3. Запустить обычным `GameServer.vbs`/`GameServerWindow.vbs` либо `GameServer.sh`. Порядок проверки/установки: debuff → arena boundary → olympiad diversity. Java25 **JDK**, не один JRE.
4. Проверить `game/log/debuff-guard-install.log` и отсутствие SEVERE о missing diversity core. При ручной установке из `game/`, после прежних двух guards:

```sh
java --class-path . core-patches/olympiad-diversity/InstallOlympiadDiversity.java ../libs/GameServer.jar core-patches/olympiad-diversity/OlympiadDiversity.java
```

В Git бинарник `libs/GameServer.jar` не заменяется: штатный launcher патчит локальный JAR перед запуском. Только hot reload скриптов недостаточен. Не меняются XML навыков, тактики, лечение, мана, лимит460, награды и начисление олимпийских очков. Для отката восстановить согласованный комплект из резервной ветки и свой проверенный pre-diversity JAR при остановленном сервере.

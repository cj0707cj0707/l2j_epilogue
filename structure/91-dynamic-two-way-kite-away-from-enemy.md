# 91. Кайт по окружности: динамический выбор стороны от противника

База: `fc7da507ea7108d00f2f74dc39a7bc9ee8fe3b7a` (90). Правила89/90 и прежняя граница арены сохранены. Это описание текущего кода, а не проверка на запущенном сервере.

## Поведение

Общий `ArenaCombatRules.kitePoint` теперь поддерживает оба направления окружности450: по часовой стрелке и против неё.

- Перед **каждым новым waypoint**, а не только при старте кайта, рассчитываются обе короткие хорды одинаковой длины.
- Выбирается сторона, конечная точка которой дальше от **текущей позиции противника**. Поэтому если противник перешёл на другую сторону, следующий шаг может сменить clockwise на counter-clockwise или обратно.
- При почти равном результате сохраняется предыдущая сторона. Допуск0.5 нужен только против integer-rounding и не фиксирует направление вопреки позиции врага.
- Перед `MOVE_TO` отдельно проверяется, что выбранная точка не уменьшает фактическое XY-расстояние до противника. Если геодата блокирует лучший путь, обратная сторона допускается только когда она тоже не ведёт ближе к врагу.
- В самой дальней доступной точке, где обе хорды начали бы сокращать дистанцию, бот стоит и перепланирует на следующем разрешённом тике вместо пробежки навстречу.
- Все waypoint по-прежнему проходят `GeoEngine.canMoveToTarget`; скорость, координаты, heading и Z не подделываются. Каст, root/CC, ownership и существующие интервалы перепланирования не обходятся.

Правило общее для всех существующих вызовов `kitePoint`: recovery/защитного кайта `BotTactics`, `InvulnerableMeleeKite`, дальнобойной реакции на неуязвимую цель и legacy `BotManager`. Специальные HOLD-фазы сна и обычное melee-преследование этим изменением не заменены.

## Изменённые файлы

| Файл | Назначение изменения |
|---|---|
| `game/data/scripts/custom/fakeplayersai/ArenaCombatRules.java` | Сравнивает clockwise/counter-clockwise на каждом шаге, разрешает динамическую смену и запрещает waypoint к противнику |
| `tests/fakeplayersai/ArenaOrbitTranceManaTest.java` | Проверяет оба направления, смену при переходе врага, удержание tie и HOLD в дальней точке |
| `tests/fakeplayersai/arena_orbit_trance_mana_tests.py` | Проверяет общее wiring всех путей, core boundary и неизменность JAR |

`BotTactics`, `BotManager`, `InvulnerableMeleeKite`, skill XML, core patch, SQL и конфигурация не изменены: они уже используют общий planner.

```bash
python tests/fakeplayersai/arena_orbit_trance_mana_tests.py
```

Результат: **26361 проверка PASS**; отдельно PASS для отсутствующего boundary-core (fail closed), hash/idempotence/tamper-проверок и неизменности исходного `GameServer.jar`. Используются настоящий `GeoEngine` wiring и установленная во временную копию JAR граница; движение мира остаётся recording seam. Это не live-проверка конкретной geodata или планировщика.

## Установка и откат

Остановить GameServer, обновить `game/data/scripts/custom/fakeplayersai/ArenaCombatRules.java` и штатно запустить GameServer. JAR/core patch, LoginServer, SQL и skill XML менять не нужно. Изменение в GitHub само по себе не установлено на работающий сервер.

Для отката вернуть `ArenaCombatRules.java` из базы90 и перезапустить GameServer. Резервная ветка: `backup/before-dynamic-kite-direction-91-2026-10-21`, указывает на базу90.

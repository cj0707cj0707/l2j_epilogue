# 35. Вход персонажей: восстановление XML навыков 1300–1399

## Симптом и подтверждённая причина

На экране выбора персонажа кнопка входа/Enter не вводили в мир. В логе от 17.10.2026:

```text
SkillData: No skill info found for skill id 1322 and skill level 1.
CharacterSelect -> GameClient.load -> Player.restore -> rewardSkills
-> giveAvailableSkills -> SkillTreeData.getAllAvailableSkills
NullPointerException: Cannot invoke Skill.getId() because skill is null
```

Та же выдача навыков вызывалась при повышении уровня ботов:
`BotSpawner.createBot -> Player.addExpAndSp -> PlayerStat.addLevel -> rewardSkills`.
Сообщения FakePlayersAI были вторым проявлением общей неисправности датапака, а не неисправностью клиентской кнопки или только одного класса.

**В репозитории `game/data/stats/skills/01300-01399.xml` содержал ровно строку `__XML_B64__` (11 байт), а не XML.** Коммит `9b9a527f6dc9245befdb1e9bb795992b1d4853f8` заменил этим маркером весь документ. Последующие коммиты восстановили три Java-скрипта, но не XML. В результате не загружались 99 определений навыков, включая общие `1322/1 Common Craft` и `1320/1..9 Create Common Item`, а также классовые умения диапазона.

Пропуск неизвестного навыка в `Player.restoreSkills` не исправляет проблему: последующий `rewardSkills` снова берёт обязательный навык из дерева, получает `null` и падает в `getAllAvailableSkills`.

## Что изменено

- Файл восстановлен **побайтно** из последней целой версии `ee21f68e96cd6e25e378ac89fde15e8a7065aaab` (родитель повреждающего коммита): 99 определений, 397 базовых шаблонов уровня после разбора настоящим ядром. Восстановлены также исходные таблицы и ветки заточки.
- SHA-256 восстановленного XML: `40c7683cb8eb9d219c24336bb15d7bc50eebfb6b3315950eb61b1e5fe4f9c528`.
- Добавлена проверка всех XML навыков по существующей XSD, полноты восстановленного диапазона и ссылок деревьев на его базовые уровни; отдельная отрицательная проверка отвергает `__XML_B64__`.
- Добавлен офлайн-тест настоящих `SkillData` и `SkillTreeData` из `libs/GameServer.jar`, с реальными effect handlers и компиляцией текущих custom-скриптов.
- Новая проверка запускается первой в общем suite, чтобы ошибка XML обнаруживалась до остальных регрессий.

**Не изменены:** `libs/GameServer.jar`, патчи ядра/установщики, запуск, конфиги, БД, клиент, Java-скрипты ботов. Последние правки AI Cardinal и остальных классов не откатывались. Никакие новые параметры баланса Trance/Mana Storm не добавлялись: XML восстановлен из реально существовавшей целой версии, а не воссоздан по заголовку повреждающего коммита. Не удалять навыки из `character_skills` и не отключать FakePlayersAI ради обхода ошибки.

## Карта файлов

| Файл | Ответственность |
|---|---|
| `game/data/stats/skills/01300-01399.xml` | Определения навыков диапазона 1300–1399: уровни, условия, эффекты, таблицы и заточки; не деревья изучения |
| `game/data/stats/players/skillTrees/**/*.xml` | Какие классы и на каком уровне получают навыки; ссылки1320/1322 оставлены без изменений |
| `game/data/xsd/skills.xsd` | Существующая схема проверки XML навыков; не изменена |
| `tests/fakeplayersai/character_login_skill_data_tests.py` | XML/XSD/preflight, ссылки деревьев, отрицательный placeholder-тест; компиляция и запуск реального core-теста |
| `tests/fakeplayersai/CharacterLoginSkillDataTest.java` | Реальная загрузка навыков и выбор доступных навыков для классов/уровней без конструктора Player, БД, сети или спавна ботов |
| `tests/fakeplayersai/suite_tests.py` | Общий прогон: новая проверка первой, прежние проверки сохранены |

`SkillData`, `SkillTreeData`, `Player`, `CharacterSelect` выполняются из JAR. Декомпилированные копии в `_olyfix/src_cur` служат справкой, не новым runtime-патчем; редактировать их для применения этого исправления не нужно.

## Проверки

```bash
python tests/fakeplayersai/character_login_skill_data_tests.py
python tests/fakeplayersai/suite_tests.py
```

Нужны Python+lxml и JDK25. Отдельный тест проверяет все 82 XML навыков (включая `custom`), ссылки деревьев на диапазон1300–1399, реальные `1320/1..9`, `1322/1` и handler `OpenCommonRecipeBook`. Проверены 397 базовых шаблонов восстановленного файла и 412 вызовов настоящего `getAllAvailableSkills` (103 непустых классовых дерева × уровни1/5/70/85).

**Результат прогона 17.10.2026:** отдельная новая регрессия прошла:82 XML/XSD,619 ссылок деревьев,99 определений/397 базовых шаблонов,412 выборок. `run_bot_combat_tests.py` также прошёл (компиляция production-скриптов,88 проверок/5000 геометрических случаев, CAST-подход и29 cycle-policy проверок). **Весь suite не зелёный:** следующая прежняя `tactics_tests.py` остановилась на `audit must cover the full eighteen-class roster`; её `presets()` ожидает18 записей и старый текстовый формат `addPreset`, тогда как нынешний BotPresets изменён предшествующими коммитами. Отдельный вызов `presets()` на неизменённом файле воспроизводит тот же отказ без чтения восстановленного XML. Последующие тесты suite после этой ошибки не выполнялись; их успех не заявляется. Проверка не отключена, её переработка и изменения AI не входят в исправление входа.

Отрицательный контроль временно удаляет1322 **только из памяти отдельной тестовой JVM**, воспроизводит NPE именно в `SkillTreeData.getAllAvailableSkills`, возвращает шаблон и проверяет успешный выбор. Предупреждение `No skill info found ...1322...` в этом контроле ожидаемо; на исправленном обычном разборе его быть не должно. Файлы датапака/JAR тест не модифицирует, к MySQL не подключается. Это проверка реального загрузчика и выбора навыков, **не проверка полного Player.restore, живого входа клиента или полного спавна ботов**.

## Применение на игровом сервере

1. Дождаться завершения тренировок/возврата игроков, остановить GameServer. Сохранить локальные правки и резерв файла, если они есть.
2. Обновить репозиторий обычным способом; убедиться, что в рабочий `game/data/stats/skills/01300-01399.xml` попал полный XML, а не placeholder. Если обновление ручное, для runtime достаточно именно восстановленного XML; тесты и `structure` — проверки/справка.
3. Запустить GameServer прежним штатным загрузчиком. Пересборка ядра, переустановка/сброс БД и перезапуск LoginServer для этого изменения не требуются.
4. Проверить журнал загрузки: нет ошибки разбора `01300-01399.xml` и сообщений об отсутствующих1320/1322 при входе/спавне.
5. Войти существующими персонажами разных классов (в том числе Cardinal/маг/боец), проверить кнопку и Enter. Проверить Common Craft и создание обычных предметов; при включённом FakePlayersAI проверить штатный спавн без прежнего NPE.

Если проблема останется, сохранить **новый** лог GameServer от загрузки XML до попытки входа. Не маскировать другую ошибку заменой ядра или удалением персонажей. Живая Windows/БД/клиентская приёмка в среде разработки не выполнялась.

## Резерв и откат

Перед изменением создана ветка `backup/before-character-login-skill-xml-fix-2026-10-17` → `d93e6fbd6d7ed648e90f1483bcec06790cd03b2a`. Это резерв репозитория, **не дамп БД**. Возвращать из неё повреждённый XML на рабочий сервер нельзя: он вернёт блокировку входа. Для исправного датапака использовать указанную целую версию XML; прочие файлы не откатывать массово.

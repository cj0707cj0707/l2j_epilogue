# 49. Кинжальщики: Escape Shackle только при руте

## Поведение

Изменение относится к управляемым ботам **Adventurer93, Wind Rider101, Ghost Hunter108** на Олимпиаде и тренировочной арене. Используется реально изученный **Escape Shackle453**, независимо от сохранённых overrides ротации/бафов. Людей и другие классы обработчик не перехватывает; отсутствующий навык не выдаёт.

1. При `bot.isRooted()` на ближайшем допустимом боевом тике проверяется453 **до обычного reaction/nextDecision-таймера**, движения/захода за спину и выбора обычного навыка.
2. Если453 готов и доступны native ресурсы/условия, бот выбирает себя и запрашивает обычный `useMagic(skill, true, true)`. Название метода ядра не означает магию: **Escape Shackle — физический SELF-навык**, в отличие от магического targeted Soul Cleanse1510.
3. Если453 на откате, нетMP, запрещён физическим молчанием или запрос отклонён, обработчик возвращает управление обычной ротации. Ожидание отката не резервирует pending и не запрещает другие доступные действия. Сам рут по-прежнему блокирует движение; дальность и условия обычных навыков не обходятся.
4. Пока рут сохраняется, готовность453 проверяется на следующих боевых тиках, даже если обычный nextDecision ещё в будущем. Как только reuse готов,453 снова получает приоритет. Реальный уже начатый/одновременный каст и pending другого навыка не прерываются.
5. Вне рута новый запрос453 невозможен. Начатая попытка доводится до разрешения pending даже если рут исчез во время каста; после этого восстанавливается цель-противник.
6.453 исключён из случайного tactical-выбора, автонавыков, автобафов и подготовки. Даже добавление453 в сохранённый override не превращает его в случайный баф/атаку. При восстановлении списка автобафов ранее попавший туда453 удаляется.
7. При реальном отказе useMagic действует существующий failure backoff (первый500мс), чтобы не спамить отклонёнными запросами. Это не дополнительный постоянный cooldown; недоступность по native reuse сама по себе не создаёт backoff.

## Штатные ограничения навыка — без изменения баланса

`game/data/stats/skills/00400-00499.xml`, skill453: **1000мс cast,15000мс reuse,60MP, target SELF, DispelBySlot ROOT_PHYSICALLY,3**. Этот XML не изменён.

Триггер ИИ — наличие настоящего ROOT (`isRooted`), не просто slow/disarm/любой movement-disabled. Снятие определяется штатным эффектом:453 снимает подходящий **физический рут**, а не гарантированно любой магический/защищённый/слишком высокий рут. Если эффект не снимается, бот продолжает обычный бой и повторяет попытку после native отката, пока root сохраняется. Ручного удаления эффектов, выдачиMP и сброса reuse нет.

Физическое молчание блокирует453; только магическое молчание не блокирует физический навык. Stun/sleep/paralyze/прочий запрещающий контроль и общий all-skills lock сохраняются. Проверка не обходит активность матча, авторизацию тренировочной пары, Olympiad restrictions и native `checkCondition`.

Мировой AutoPlay отдельным обработчиком453 не расширялся. При отключённом tactical-драйвере эта условная аренная механика не работает;453 всё равно не должен расходоваться случайной авторотацией.

## Проверки

Команда: `python3 tests/fakeplayersai/escape_shackle_tests.py` — **377 проверок, прошли**; все custom/effect-скрипты компилируются против поставленных JAR.

Проверяются оба arena-режима и все три класса: без рута нет каста; с рутом453 приоритетнее будущего nextDecision; pending/self-target/возврат противника; граница59/60MP; cooldown и повтор при сохраняющемся root; запреты физического молчания/CC, отсутствие запрета от одного magic silence; чужой pending/реальный каст; отказ и backoff; люди, другие классы, mismatch preset/класса и отсутствие изученного навыка. Отдельно вызывается настоящая обычная ротация под root при недоступном453: доступный Ultimate Evasion111 должен быть выбран, а не заблокирован ожиданием.

Также проверен публичный `BotTactics.tick`: разрешённая пара достигает453, pending не дублируется, подготовка/завершённая тренировка/неактивный матч не получают каст. `refreshAutoBuffs` удаляет ранее попавший в пул453. Source guards проверяют фильтры override/автопулов; полный live AutoUse scheduler тестом не запускается.

Смежные регрессии прошли: `dagger_rear_approach_tests.py`3168, `berserker_soul_cleanse_tests.py`714, `low_mana_autoattack_tests.py`2531, `combat_recovery_rules_tests.py`1126, `cp_melee_rush_recovery_tests.py`29287+458, `cardinal_arena_parity_tests.py`6062, `cardinal_spawn_dagger_pressure_tests.py`876, `berserker_body_reconstruction_tests.py`94. Это выбранные затронутые проверки, не весь legacy test-suite.

Фикстура использует настоящий код Player/Skill и существующую основу `BerserkerSoulCleanseTest`; только `useMagic`, `setTarget`, `getTarget` — записывающие override через Java25 classfile API. Кастовый scheduler, клиент, БД и фактическое снятие эффекта на живом GameServer не запускались. Проверки не заменяют live smoke.

## Применение / откат

1. Остановить GameServer, сохранить текущие `BotTactics.java` и `BotSpawner.java`.
2. Обновить **оба** production-файла согласованно поверх текущей версии с изменениями47/48. JAR, skill XML, ini, registry и БД заменять не требуется.
3. Полностью перезапустить GameServer для компиляции скриптов; не hot reload.
4. Live smoke для93/101/108 в тренировке и Олимпиаде: при готовом453/достаткеMP наложить подходящий физический root — немедленный приоритет453; повторить root во время reuse — доступная обычная ротация продолжается, после окончания reuse453 применяется снова. Снять root до готовности —453 не тратится. Проверить физическое молчание, нехваткуMP, чужой активный каст, магический/неснимаемый root и override с453. Заход за спину раз в2с из47 остаётся, но невозможен до освобождения от рута.

Откат: при остановленном GameServer вернуть оба production-файла из согласованного резерва или базового коммита `46025203936742070fe9c731985353e9126ec297`, затем полный перезапуск. Миграций данных нет.

# 81. Root от танка: временная ротация с места вместо кайта

База: `eabeca70dc62eaacf37c13fd8cf87cabf581f479` (80).
Резервная ветка: `backup/before-tank-root-stationary-rotation-2026-10-20`.

## Исправленное поведение

Раньше общий escape-hook при сильной защите танка доходил до `isMovementDisabled()`, прекращал движение и возвращал «ход обработан». Весь ход оставался за кайтом, поэтому доступные стационарные навыки не рассматривались.

Теперь при **реально действующем root от текущего противника-танка**:

1. Старый кайт останавливается. Управление временно переходит полноценной обычной ротации, а не только защитной поддержке перед движением.
2. Выбираются изученные навыки, которые можно законно применить с текущего места. Сохраняются native дальность/LOS, MP, cooldown, оружие/заряды/предметы, silence/CC, condition, реакция AI и backoff. Нет walk-to-cast, подмены координат или снятия root ради атаки.
3. Пока root действует, повторный общий или Cardinal survival-кайт не забирает ход. Фильтры «сначала подойти» у мили/танков не скрывают доступный дальний навык; реальная дальность каждого навыка по-прежнему проверяется. Shadow Step и charge-навыки остаются запрещены при невозможности двигаться.
4. Разрешённый прежней ротацией fallback к автоатаке возможен только уже в физической дальности с LOS по бодрствующей уязвимой цели. Вне дальности бот ждёт; родительскому chase-драйверу ход не отдаётся. Прежние запреты автоатаки у кинжальщиков/магов сохраняются.
5. Root закончился, а причина кайта осталась — возобновляется прежний кайт. Если сильная защита/неуязвимость закончилась раньше root, бот продолжает стационарную ротацию до его окончания, затем освобождает специальную фазу. Если кайт уже не нужен, он не запускается заново.

### Какие эффекты учитываются

Нужны одновременно native `isRooted()`, активный не удалённый `BuffInfo`, правильные effector/effected, актуальная запись abnormal-stack и настоящий не instant эффект `ROOT` с флагом `ROOTED`. Противник должен принадлежать одной из четырёх native веток танков, включая Eva's Templar. Это работает против танка-игрока и танка-бота в существующих авторизованных боях олимпиады/тренировки.

Один флаг, старый/неактивный эффект, стан, собственное обездвиживание, root от другого персонажа или не-танка не включают эту узкую ветку. Люди-цели root не получают управление ботом.

### Сохраняемые приоритеты

- Настоящий текущий cast/pending не отменяется ради переключения фазы.
- Законные Soul Cleanse/Escape Shackle остаются выше обычной атаки; если навык действительно снимет root, дальнейший кайт решается по текущему состоянию.
- Сон защищённого танка у Dominator по правилу80 остаётся отходом/HOLD: root не является разрешением будить его уроном. Под root отход недоступен, значит сохраняется HOLD и допустимая self-поддержка.
- Cardinal сохраняет свой сон/HOLD, приоритет лечения ниже75%, здорового Prominence и Trance. Приоритет готового Cancel у Archmage/Mystic Muse также сохранён.
- У Doombringer временно не используется тренировочная rush-only фаза, требующая движения; работает обычный подбор доступных навыков. Native запрет charge под root не обходится. Обязательный hook сохраняет владение ходом и в ranked131.
- Шансы/время сна, Bluff, экипировка, длительность матчей, радиус кайта и native эффекты танков не изменялись.

```bash
python tests/fakeplayersai/passive_barrier_bluff_tests.py --tank-root-only
python tests/fakeplayersai/passive_barrier_bluff_tests.py
```

Результат проверки81: отдельный root-прогон **13 602 PASS**, затем полный прогон **всех17 suites PASS**; все custom/effect/target scripts и AdminBot скомпилированы. `git diff --check` — чисто. SHA256 исходного `libs/GameServer.jar`: `8f27196ca9d74b82bbe9ad0d12d70da0196fa4e0d1bf23595267b724c79a23dd` (без изменений).

Тесты используют копию native JAR во временной папке и recording seams вместо live world/БД/клиента. Это не является проверкой реального боя на запущенном сервере.

На локальный сервер нужно перенести два изменённых production Java-файла из таблицы, затем полностью перезапустить GameServer для перекомпиляции скриптов. Ядро заменять и переустанавливать core-patches не требуется. В `C:\EpilogueServer` изменения автоматически не устанавливались.

Ручной сценарий: бот кайтит танка под110/368/760 → танк накладывает root → бот прекращает маршрут и использует доступные с места навыки → root заканчивается, защита ещё активна → кайт продолжается. Отдельно проверить root вместе со станом/silence, цель вне дальности и спящего танка: запреты должны оставаться действующими.

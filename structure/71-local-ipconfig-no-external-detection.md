# 71. Локальный IP без внешнего автоопределения при запуске

## Причина

В установленном `libs/GameServer.jar`, `ServerConfig$IPConfigData.load()` проверяет **`./config/ipconfig.xml` относительно рабочего каталога GameServer (`game/`)**. При отсутствии файла пишет `Network Config: ipconfig.xml does not exist, using automatic configuration...` и вызывает `autoIpConfig()`.

Автоматическая ветка делает синхронный HTTP-запрос к `http://checkip.amazonaws.com` через `URL.openStream()` без явно заданных connect/read timeout. Ожидание сети/DNS может объяснять сообщённую паузу30–40с; длительность на пользовательском ПК не измерялась. Затем перечисляются локальные сетевые интерфейсы. Существующий `default-ipconfig.xml` загрузчик не читает: это только образец, не активная настройка.

## Исправление и карта файлов

| Файл | Ответственность |
| --- | --- |
| `game/config/ipconfig.xml` | **Новый активный XML.** Default address127.0.0.1 и явное правило127.0.0.0/8→127.0.0.1. Включает ручную ветку загрузчика; внешний IP больше не определяется. |
| `game/config/default-ipconfig.xml` | Неизменённый пример конфигурации; имя не активирует загрузку. Не копировать его LAN-заглушки10/172/192 в локальную конфигурацию. |
| `game/data/xsd/ipconfig.xsd` | Неизменённая native XSD, которой соответствует новый XML. |
| `tests/network/LocalIpConfigTest.java` | Изолированный тест реального загрузчика из GameServer.jar: XSD, manual-ветка, loopback/fallback, отсутствие HTTP. Режим auto-probe проверяет ветку отсутствующего XML, блокируя запрос до сети. |
| `structure/03-game-config.md`, `04-login-server.md`, `README.md` | Актуальная карта активного XML и ссылки на эту инструкцию. |

Вручную parser добавляет fallback0.0.0.0/0→127.0.0.1 из корневого address. Все выдаваемые клиенту адреса ведут на тот же ПК. Имя `localhost` не используется, чтобы не требовалось его разрешение.

Это **выдаваемый клиентам IP**, не изменение bind/firewall: `GameserverHostname=0.0.0.0` и `LoginserverHostname=0.0.0.0` оставлены прежними. Изменение не заявляется сетевой изоляцией процесса. Межсерверные LoginHost/LoginHostname127.0.0.1, порты, hexid, БД, клиенты и JAR не меняются. Подключение с других ПК этой конфигурацией не поддерживается.

## Проверки

Из корня репозитория:

```sh
cd game
java --class-path '../libs/*' ../tests/network/LocalIpConfigTest.java
```

На Windows в каталоге `game`:

```bat
java --class-path "../libs/*" ../tests/network/LocalIpConfigTest.java
```

Результат: PASS — native XSD, manual-ветка, hosts=[127.0.0.1,127.0.0.1], subnets=[127.0.0.0/8,0.0.0.0/0], **0 HTTP-запросов**, без ошибок XML. В изолированной проверке загрузчик выполнился примерно за44мс; это не время полного запуска GameServer.

Дополнительно в отдельном временном рабочем каталоге без `config/ipconfig.xml` запущен тот же тест с аргументом `auto-probe`: обнаружен ровно один HTTP-вызов, заблокированный тестовым URL-handler до обращения к сети. Подтверждены automatic-ветка и fallback; реальный внешний сервис не вызывался.

Полный GameServer с БД не запускался; время запуска на пользовательском компьютере не измерялось. Изменение убирает конкретное ожидание внешнего IP, но не гарантирует отсутствие иных задержек загрузки.

## Установка

1. Скопировать **`game/config/ipconfig.xml`** из репозитория в **`C:\EpilogueServer\game\config\ipconfig.xml`**. Не в `login/config`, не рядом с `GameServer.vbs` и не под именем `default-ipconfig.xml` или `ipconfig.xml.txt`.
2. Полностью перезапустить GameServer. Отдельный рестарт LoginServer для этой правки не нужен. Штатные VBS/SH-launchers уже устанавливают рабочий каталог `game`.
3. Ожидаемая строка: `Network Config: ipconfig.xml exists, using manual configuration...`. Проверить вход локальным клиентом; он должен обращаться к LoginServer на127.0.0.1.
4. Если всё ещё появляется `does not exist`, проверять фактический путь файла, расширение и рабочий каталог запуска. Если появляется manual-строка, но пауза остаётся — сравнить временные отметки следующих строк: причина уже не в данном HTTP-автоопределении.

## Откат

База до изменения: `20797f7231bf9ef340af3d78c53af0f6551e2297`. Удаление/переименование `game/config/ipconfig.xml` и перезапуск вернут автоматическое определение вместе с возможным ожиданием сети. Остальные предыдущие исправления откатывать не нужно. Для будущего доступа с других ПК потребуется отдельная настройка адресов; текущая задача рассчитана только на один компьютер.
